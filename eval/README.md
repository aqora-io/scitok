## Data

`data/`, `domains/` and `results/` are not versioned. That includes the agent-written queries,
the qrels and the acronym gold sets, which cannot be regenerated by the steps below.

1. Harvest both periods into the scitok-learn cache:

   ```bash
   cargo run --release -p scitok-learn -- fetch --category quant-ph --from 2025-10-15 --until 2026-04-14
   cargo run --release -p scitok-learn -- fetch --category quant-ph --from 2026-04-15 --until 2026-10-15
   ```

2. Build the eval domain from the older period only, with the curated lexicon copied in:

   ```bash
   mkdir -p eval/domains/quant-ph
   cp crates/scitok/data/domains/quant-ph/curated.toml eval/domains/quant-ph/
   cargo run --release -p scitok-learn -- build --category quant-ph --from 2025-10-15 --until 2026-04-14 --out eval/domains/quant-ph
   ```

3. Prepare the corpus and the proxy query sets:

   ```bash
   eval/.venv-sci/bin/python eval/prepare.py
   eval/.venv/bin/python eval/prepare_acronym_hard.py
   ```

4. Domain variants for tuning, including `variants/mc3-npmi0.5-mp1500` used as "scitok tuned":

   ```bash
   cd eval && .venv/bin/python tune_domain.py
   ```

5. LLM-refined variant, plus review-only and expand-only ablations. Needs `OPENAI_API_KEY`;
   responses are cached in `.scitok-cache/quant-ph/llm/`.

   ```bash
   cp -r eval/domains/variants/mc3-npmi0.5-mp1500 eval/domains/variants/mc3-npmi0.5-mp1500-llm
   cargo run --release -p scitok-learn -- refine --category quant-ph --from 2025-10-15 --until 2026-04-14 \
       --model gpt-6.1-sol --out eval/domains/variants/mc3-npmi0.5-mp1500-llm
   ```

   The ablations are copies of the base variant:
   - review-only: its `reviewed.toml` is the refined one minus the "Added variants" section;
   - expand-only: its `reviewed.toml` is `mined.toml` plus the added variants, with renamed
     canonicals mapped back.

   Pass each lexicon's BM25 `avg_len`, recomputed on the mining corpus, explicitly: for example
   `scitok:domain=mc3-npmi0.5-mp1500-llm,avg_len=115.9`.

Agent queries (`data/queries_agent.jsonl`) and judgments (`data/qrels_agent.jsonl`) were produced
by Claude subagents:
- `pool.py write` creates blind judging batches and alias keys under `data/agent/judge_v2/`.
  Judges followed `data/agent/judge_v2/JUDGE_PROMPT.md`.
- `pool.py merge` builds the qrels from the raw judgments and the alias keys.

## Running

```bash
cd eval
.venv/bin/python encode_all.py                 # cache slow encoders (hours on CPU)
.venv/bin/python run.py --tasks agent,title,acronym,acronym_hard --split test \
    --systems "scitok;scitok:domain=mc3-npmi0.5-mp1500,compounds=false,concept_weight=0.5;bm25s;fastembed-bm25"
.venv/bin/python pool.py coverage "scitok;arctic-m" --split test   # share of top-10 that is judged

.venv-sci/bin/python acronym_eval.py predict-sci heldout
.venv/bin/python acronym_eval.py predict-scitok heldout
.venv/bin/python acronym_eval.py score heldout
```

System names:
- Baselines are listed in `systems.baselines()`.
- `scitok:<option>=<value>,...` sets tokenizer options. `domain=<variant>` selects
  `domains/variants/<variant>`; `domain=none` uses no domain.
- `<baseline>:text=clean|expand,input=auto|plain,domain=<variant>,side=both|query` runs a
  baseline on scitok's `clean` or `expand` text instead of the raw text, for documents and queries
  or for queries only. For example: `arctic-m:text=expand,side=query`.
- `rrf:A+B` fuses two systems with reciprocal rank fusion.

Results are merged into `results/<task>-<split>.json` (not versioned; the reported numbers are in
[RESULTS.md](RESULTS.md)).
